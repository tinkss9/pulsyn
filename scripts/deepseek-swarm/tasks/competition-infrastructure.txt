# Task: Build Competition Infrastructure

## Objective
Build the real competition infrastructure for the Pulsyn Replication Race — real benchmark engine, Docker-based isolation, transparent metrics.

## Current State
- Competition page exists at `packages/web/src/app/competition/page.tsx` (now shows "Coming Soon")
- Benchmark engine exists at `packages/core/src/benchmark/engine.ts` (simulated)
- No real competition infrastructure

## What Needs to Be Built

### 1. Real Benchmark Runner (Already Spawned)
- See T3 task for benchmark runner implementation
- Must measure real throughput, latency, correctness

### 2. Docker-Based Isolation
Create `docker/competition/` directory with:
- `docker-compose.competition.yml` — Defines isolated containers for each competitor
- Each container gets:
  - Source database (PostgreSQL, MySQL, or MongoDB)
  - Target database (PostgreSQL, MySQL, or Snowflake)
  - Pulsyn CLI installed
  - Network isolation (can't access other containers)
  - Resource limits (CPU, memory)

### 3. Competition API
Create `packages/web/src/app/api/competition/` routes:
- `POST /api/competition/register` — Register for competition
- `POST /api/competition/start` — Start a competition run
- `GET /api/competition/status/[runId]` — Get run status
- `GET /api/competition/leaderboard` — Get leaderboard
- `POST /api/competition/submit` — Submit connector code

### 4. Scoring System
Create `packages/core/src/competition/scoring.ts`:
- Throughput score (rows/sec) — 40% weight
- Latency score (p99 ms) — 30% weight
- Correctness score (data integrity) — 30% weight
- Anti-cheat: verify runs happen on our infrastructure

### 5. Leaderboard
Create `packages/web/src/app/competition/leaderboard/page.tsx`:
- Real-time leaderboard (not fabricated)
- Show: rank, name, score, rows/sec, latency, country
- Filter by: week, phase, connector pair
