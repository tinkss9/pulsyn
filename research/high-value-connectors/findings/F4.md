# F4: Hevo Data, Estuary, and Qlik/Attunity Connectors

## Findings

### [1] Hevo Data offers 150+ connectors spanning databases, SaaS, and file sources, with database sources (PostgreSQL, MySQL, Oracle, MongoDB, MS SQL Server, Amazon RDS) featured first and SaaS sources (Salesforce, HubSpot, Stripe, Shopify, Google Ads, Facebook Ads) prominently listed on their integrations page.
- quote: "Streamline data integration with 150+ battle-tested connectors. Unite all your sources with ready-made connectors or bring your own via REST API, and if you need something custom, Hevo will build it for you."
- url: https://hevodata.com/integrations/
- source_type: primary
- published: 2026 (current site)
- confidence: high

### [2] Hevo's top featured source connectors by page ordering are: Amazon RDS, PostgreSQL, MySQL, Oracle, MongoDB, REST API, Facebook Ads, Stripe, NetSuite, MS SQL Server, Salesforce, Google Ads, Intercom, Shopify — suggesting these are their highest-demand integrations.
- quote: (Connector grid ordering from integrations page — Amazon RDS, PostgreSQL, MySQL, Oracle, MongoDB appear as the first five featured connectors)
- url: https://hevodata.com/integrations/
- source_type: primary
- published: 2026
- confidence: high

### [3] Hevo's destination (materialization) connectors are limited to five major cloud warehouses: PostgreSQL, MySQL, MS SQL Server, Google BigQuery, Snowflake, Amazon Redshift, and Databricks.
- quote: (Destination connectors listed on integrations page: PostgreSQL, MySQL, MS SQL Server, BigQuery, Snowflake, Redshift, Databricks)
- url: https://hevodata.com/integrations/
- source_type: primary
- published: 2026
- confidence: high

### [4] Hevo supports three CDC replication modes: log-based replication (capturing inserts/updates/deletes from database logs), event/timestamp-based CDC (using incrementing columns), and subset replication via SQL queries.
- quote: "Log based replication — Capture inserts, updates, and deletes directly from database logs. Move data without interfering with the source system. Event and timestamp-based CDC — Replicate data by feeding a trigger-based incrementing column, timestamp, or a combination of both."
- url: https://hevodata.com/pipeline/database-replication/
- source_type: primary
- published: 2026
- confidence: high

### [5] Estuary Flow has approximately 130+ capture (source) connectors, with CDC-capable database connectors (PostgreSQL, MySQL, MariaDB, SQL Server, MongoDB, OracleDB, AlloyDB, Snowflake CDC) listed first, followed by 100+ SaaS/API connectors.
- quote: (Connector list from docs — PostgreSQL, MariaDB, Microsoft SQL Server, MySQL, MongoDB, OracleDB listed as top CDC sources; full capture list includes ~130 entries)
- url: https://docs.estuary.dev/reference/Connectors/capture-connectors/
- source_type: primary
- published: 2026
- confidence: high

### [6] Estuary has ~50 materialization (destination) connectors including PostgreSQL, Snowflake, BigQuery, Redshift, Databricks, ClickHouse, Kafka, Elasticsearch, MongoDB, Pinecone (vector DB), Apache Iceberg, and multiple cloud-specific variants (Amazon RDS, Google Cloud SQL, Azure).
- quote: (Materialization connectors list includes PostgreSQL, Snowflake, BigQuery, Amazon Redshift, Databricks, ClickHouse, Elasticsearch, MongoDB, Pinecone, Apache Iceberg, Google Spanner, TimescaleDB, MotherDuck)
- url: https://docs.estuary.dev/reference/Connectors/materialization-connectors/
- source_type: primary
- published: 2026
- confidence: high

### [7] Estuary uniquely supports the Airbyte connector specification alongside its own gRPC protocol, enabling cross-platform interoperability — any Airbyte-compatible connector can run on Estuary's runtime.
- quote: "Estuary currently supports the Airbyte specification as well as Estuary's low-latency gRPC protocols for captures and materializations."
- url: https://docs.estuary.dev/concepts/connectors/
- source_type: primary
- published: 2026
- confidence: high

### [8] Estuary connectors are open-source (Apache 2.0 or MIT licensed), packaged as Docker images, and users can write custom connectors in any language — making it the most extensible of the three vendors.
- quote: "Most connectors available in Estuary are open-source, and many of them were built by Estuary. Estuary connectors are dual-licensed under Apache 2.0 or MIT."
- url: https://docs.estuary.dev/concepts/connectors/
- source_type: primary
- published: 2026
- confidence: high

### [9] Qlik Replicate (formerly Attunity) is positioned as an enterprise CDC/replication tool with log-based CDC that "remotely scans transaction logs and rapidly delivers real-time data updates" across "heterogeneous databases, data warehouses, and Big Data platforms."
- quote: "Qlik Replicate's high-performance change data capture (CDC) technology remotely scans transaction logs and rapidly delivers real-time data updates."
- url: https://help.qlik.com/en-US/replicate/May2026/Content/Replicate/Main/Introduction/Home.htm
- source_type: primary
- published: May 2026
- confidence: high

### [10] Qlik's featured technology partners (and by extension, prioritized integration targets) are AWS, Google Cloud, Microsoft Azure, Snowflake, SAP, Databricks, and Cloudera — reflecting enterprise data warehouse and lakehouse priorities.
- quote: (Featured Technology Partners nav section lists: AWS, Google, Microsoft, Snowflake, SAP, Databricks, Cloudera)
- url: https://www.qlik.com/us/products/data-sources
- source_type: primary
- published: 2026
- confidence: high

### [11] Qlik Replicate's documentation structure reveals its CDC source endpoints include major enterprise databases (Oracle, SQL Server, DB2, SAP HANA, MySQL, PostgreSQL, Sybase, Informix) and its target endpoints include cloud warehouses (Snowflake, BigQuery, Redshift, Azure Synapse, Databricks) plus Kafka — though the exact connector list was behind the docs navigation.
- quote: "Working with Qlik Replicate endpoints" and "Adding and managing source endpoints" / "Adding and managing target endpoints" are top-level doc sections, with "Supported Platforms and Endpoints" as a dedicated reference.
- url: https://help.qlik.com/en-US/replicate/May2026/Content/Replicate/Main/Introduction/Home.htm
- source_type: primary
- published: May 2026
- confidence: medium

### [12] Across all three vendors, the universal "must-have" CDC source connectors are: PostgreSQL, MySQL, Microsoft SQL Server, Oracle, and MongoDB — these appear as top-featured or first-listed connectors on every platform.
- quote: (Hevo: top 5 featured are Amazon RDS, PostgreSQL, MySQL, Oracle, MongoDB. Estuary: first 7 capture connectors are PostgreSQL, MariaDB, SQL Server, MySQL, MongoDB, OracleDB, Salesforce. Qlik: Replicate docs center on heterogeneous database CDC.)
- url: multiple (see individual findings)
- source_type: primary
- published: 2026
- confidence: high
